# Прикладной уровень (Application Level Service)

Сервис прикладного уровня системы управления станком с ЧПУ. Объединяет веб-интерфейс (SPA) оператора и серверную часть на Node.js, которая выполняет валидацию управляющих программ, проксирует валидированные команды на агентный уровень, принимает агрегированные состояния от транспортного уровня и рассылает их клиентам по протоколу Server-Sent Events (SSE).

## Стек технологий

* **Frontend:** React 18, Redux Toolkit, Axios
* **Backend / SSE-сервер:** Node.js 22 (`node:http`, без внешних зависимостей)
* **Сборка и локальная разработка:** Vite
* **Контейнеризация:** Docker, Docker Compose

## Архитектура и взаимодействие уровней

```text
[ Браузер оператора ]
        │
        ├── POST /api/v1/commands ───────► [ App Server (:3000) ] ──► [ Agent Level (:8002) ]
        │                                    (валидация УП)
        └── GET  /api/v1/telemetry/stream ◄─ [ App Server (:3000) ] ◄── POST /api/v1/telemetry ── [ Transport Level (:8001) ]
                                             (SSE-брокер + ping)
```

Все взаимодействия браузера проходят через единую точку входа `server.mjs` (порт `3000`). Клиентское приложение не хранит адресов смежных микросервисов и не выполняет парсинг управляющих программ.

## Основной функционал

### 1. Серверная валидация и отправка команд (`server.mjs`, `commandValidator.mjs`)
При поступлении запроса `POST /api/v1/commands` сервер выполняет полную проверку управляющей программы до обращения к агентному уровню:
* **Синтаксис текстового формата:**
  * Сверление: `D <x> <y> <depth> <duration>` или `S <x> <y> <depth> <duration>` (4 числовых параметра).
  * Фрезеровка: `F <startX> <startY> <endX> <endY> <depth> <duration>` (6 числовых параметров).
  * Игнорирование пустых строк и комментариев (`#`, `//`).
* **JSON-формат:** проверка валидности JSON, структуры объекта операции и обязательных полей.
* **Технологические ограничения:** проверка попадания координат в рабочую зону `[0..1000]`, положительных значений глубины `(0..100]` и длительности `(0..3600]`, а также ненулевой длины траектории при фрезеровке.
* **Маршрутизация на агентный уровень:** при ошибке валидации клиенту возвращается `400 Bad Request` (`source: "validation"`). Корректная одиночная операция отправляется на `POST /api/v1/commands`, пакет операций — на `POST /api/v1/commands/batch` агентного уровня.

### 2. SSE-сервер и приём телеметрии (`server.mjs`)
* `POST /api/v1/telemetry` — внутренний эндпоинт для транспортного уровня. Принимает собранное состояние станка или сообщение об ошибке сборки сегментов и транслирует его всем активным SSE-клиентам, сбрасывая таймер пинга.
* `GET /api/v1/telemetry/stream` — SSE-поток для браузера оператора. При отсутствии новых сообщений от транспортного уровня в течение `PING_INTERVAL_MS` (по умолчанию `1500` мс) отправляет событие `event: ping`.

### 3. Диагностика канала связи в UI (`src/store/telemetrySlice.js`)
* **Обновление состояния:** при получении `event: telemetry` обновляются фаза обработки (`idle`, `retract`, `positioning`, `plunge`, `drilling`, `milling`, `return_home`) и координаты `(X, Y, Z)`. При переходе в режим ожидания (`finished: true` или `idle`) сбрасывается индикатор нестабильности и выводится уведомление о завершении цикла.
* **Индикация нестабильного соединения:** отслеживается скользящее окно из последних **5 событий телеметрии** с начала выполнения команд. Если среди них зафиксирована хотя бы одна ошибка (`error: true`), рядом с параметрами станка отображается предупреждение *«Нестабильное соединение»*.
* **Обработка пингов и обрывов (`event: ping`):**
  * **1-й пинг во время работы станка:** вместо параметров станка отображается сообщение *«Соединение прервано»*.
  * **2-й пинг подряд в прерванном состоянии:** состояние станка сбрасывается в исходное (`Ожидание`, `X: 0 | Y: 0 | Z: 0`), восстанавливается отображение параметров, а в чат добавляется сообщение о сбросе состояния из-за потери соединения.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
| :--- | :--- | :--- |
| `PORT` | Порт HTTP/SSE-сервера прикладного уровня | `3000` |
| `AGENT_URL` | Базовый URL агентного уровня | `http://localhost:8002` (в Docker: `http://host.docker.internal:8002`) |
| `PING_INTERVAL_MS` | Интервал отправки SSE-пингов при простое (в миллисекундах) | `1500` |

## Запуск и сборка

### 1. Запуск в Docker (Production)

Создайте файл `.env` (при необходимости) и запустите контейнер:

```bash
docker compose build --no-cache
docker compose up -d
```

Для подключения к агентному уровню на удалённом узле (например, в сети ZeroTier) передайте переменную `AGENT_URL`:

```bash
AGENT_URL=http://<IP_АГЕНТА>:8002 docker compose up -d
```

Проверка работы контейнера:

```bash
docker compose ps
docker compose logs -f application-service
```

### 2. Локальный запуск для разработки (без Docker)

В первом терминале запустите сервер прикладного уровня:

```bash
AGENT_URL=http://localhost:8002 node server.mjs
```

Во втором терминале установите зависимости и запустите dev-сервер Vite (порт `5173`, проксирует `/api/v1` на `:3000`):

```bash
npm install --legacy-peer-deps
npm run dev
```
