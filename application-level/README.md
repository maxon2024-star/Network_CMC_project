# Прикладной уровень (Application Level Service)

Веб-интерфейс (SPA) оператора станка с ЧПУ. Сервис обеспечивает авторизацию пользователя, ввод и валидацию управляющих программ (в текстовом формате и через загрузку файлов), отправку команд на агентный уровень и отображение телеметрии станка в реальном времени по протоколу Server-Sent Events (SSE).

---

## Стек технологий

* **Frontend:** React 18, Redux Toolkit, Axios
* **Сборка и локальная разработка:** Vite
* **Production-сервер и обратный прокси:** Nginx (`nginx:1.27-alpine`)
* **Контейнеризация:** Docker, Docker Compose

---

## Архитектура и взаимодействие уровней

```text
[ Браузер оператора ]
        │
        ├── POST /api/v1/commands(/batch) ──► [ Nginx / Vite Proxy (:3000) ] ──► [ Agent Level (:8002) ]
        │
        └── GET  /api/v1/telemetry/stream ◄── [ Nginx / Vite Proxy (:3000) ] ◄── [ Transport Level (:8001) ]
```

Для исключения ограничений CORS и упрощения сетевой конфигурации все запросы из браузера выполняются по относительным путям `/api/v1/...` на порт `3000`, откуда прозрачно проксируются в целевые микросервисы.

## Основной функционал

### 1. Валидация управляющих программ (`src/api/cncApi.js`)
Перед отправкой на агентный уровень каждая команда проверяется на клиенте:
* **Синтаксис текстового формата:**
  * Сверление: `D <x> <y> <depth> <duration>` или `S <x> <y> <depth> <duration>` (ровно 4 числовых параметра).
  * Фрезеровка: `F <startX> <startY> <endX> <endY> <depth> <duration>` (ровно 6 числовых параметров).
  * Поддержка пустых строк и комментариев (`#`, `//`).
* **JSON-формат:** проверка валидности JSON, структуры объекта операции и обязательных полей.
* **Технологические ограничения:** проверка попадания координат в рабочую зону `[0..1000]`, положительных значений глубины `(0..100]` и длительности `(0..3600]`, а также ненулевой длины траектории при фрезеровке.
* **Маршрутизация запросов:** одиночная операция отправляется на `POST /api/v1/commands`, программа из нескольких операций — на `POST /api/v1/commands/batch`.

### 2. Обработка SSE-потока и диагностика канала связи (`src/store/telemetrySlice.js`)
* **Обновление телеметрии:** при получении события `telemetry` обновляются текущая фаза обработки (`idle`, `retract`, `positioning`, `plunge`, `drilling`, `milling`, `return_home`) и координаты `(X, Y, Z)`. При `finished: true` в чат выводится уведомление о завершении цикла.
* **Индикация нестабильного соединения:** отслеживается скользящее окно из последних **5 событий телеметрии** с начала выполнения команд. Если среди них зафиксирована хотя бы одна ошибка сборки сегментов (`error: true`), рядом с параметрами станка отображается предупреждение *«Нестабильное соединение»*.
* **Обработка пингов и обрывов (`event: ping`):**
  * **1-й пинг во время работы станка:** вместо параметров станка отображается сообщение *«Соединение прервано»*.
  * **2-й пинг подряд в прерванном состоянии:** состояние станка принудительно сбрасывается в исходное (`Ожидание`, `X: 0 | Y: 0 | Z: 0`), восстанавливается отображение параметров, а в чат добавляется сообщение о сбросе состояния из-за потери соединения.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
| :--- | :--- | :--- |
| `VITE_TRANSPORT_SSE_URL` | Относительный путь к SSE-потоку в браузере | `/api/v1/telemetry/stream` |
| `VITE_AGENT_API_URL` | Базовый относительный путь к API агента в браузере | `/api/v1` |
| `PROXY_TRANSPORT_URL` | Целевой URL транспортного уровня для dev-прокси Vite | `http://localhost:8001` |
| `PROXY_AGENT_URL` | Целевой URL агентного уровня для dev-прокси Vite | `http://localhost:8002` |
| `DOCKER_TRANSPORT_URL` | Целевой URL транспортного уровня для Nginx в Docker | `http://host.docker.internal:8001` |
| `DOCKER_AGENT_URL` | Целевой URL агентного уровня для Nginx в Docker | `http://host.docker.internal:8002` |

## Запуск и сборка

### 1. Локальный запуск для разработки (без Docker)

Установите зависимости и запустите dev-сервер Vite:

```bash
npm install
npm run dev
```

Приложение будет доступно по адресу `http://localhost:3000`.

### 2. Запуск в Docker (Production)

Соберите образ и запустите контейнер:

```bash
docker compose build --no-cache
docker compose up -d
```

Для подключения к транспортному и агентному уровням на удалённых узлах (например, в сети ZeroTier) задайте переменные `DOCKER_TRANSPORT_URL` и `DOCKER_AGENT_URL` перед запуском:

```bash
DOCKER_TRANSPORT_URL=http://<IP_ТРАНСПОРТА>:8001 DOCKER_AGENT_URL=http://<IP_АГЕНТА>:8002 docker compose up -d
```

Проверка работы контейнера и активной конфигурации Nginx:

```bash
docker compose ps
docker compose exec application-service cat /etc/nginx/conf.d/default.conf
```
