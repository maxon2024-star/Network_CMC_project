# Агентный уровень (Agent Level Service)

Микросервис эмуляции работы станка с ЧПУ и управления его кинематикой. Сервис принимает одиночные и пакетные управляющие программы от прикладного уровня, симулирует движение резца в трёхмерном пространстве $(X, Y, Z)$ через внутреннюю шину ROS 2, сегментирует данные телеметрии и передаёт их на транспортный уровень.

---

## Стек технологий

* **Backend / API:** Python 3.11+, FastAPI, Uvicorn, Pydantic
* **Интеграция и симуляция:** ROS 2 (`rclpy`), `std_msgs`
* **HTTP-клиент:** `httpx` (асинхронная отправка сегментов)
* **Контейнеризация:** Docker, Docker Compose

---

## Архитектура и взаимодействие уровней

```text
[ Application Level (:3000) ]
             │
             ▼  POST /api/v1/commands(/batch)
┌────────────────────────────────────────────────────────┐
│                 Agent Level (:8002)                    │
│                                                        │
│  [ FastAPI ] ──► [ ROS 2 Node: cnc_machine_node ]      │
│                         │  (кинематика 10 Гц)          │
│                         ▼  топик /cnc/telemetry        │
│                  [ Telemetry Segmenter ]               │
└─────────────────────────┬──────────────────────────────┘
                          │  POST /api/v1/segments (Base64 чанки)
                          ▼
              [ Transport Level (:8001) ]
```

## Основной функционал

### 1. Приём и валидация команд (`app/main.py`, `app/models.py`)
Сервис предоставляет REST API для постановки технологических операций в очередь выполнения станка:
* `POST /api/v1/commands` — приём одиночной команды (`drilling` или `milling`), постановка в очередь и немедленный возврат статуса `202 Accepted`.
* `POST /api/v1/commands/batch` — приём массива команд в рамках единой управляющей программы с сохранением порядка выполнения.
* Валидация входящих параметров (координат `start`/`end`, глубины `depth`, длительности `duration`) с помощью Pydantic.

### 2. Кинематическая модель и ROS 2 (`app/cnc_node.py`)
Узел `cnc_machine_node` выполняет симуляцию работы станка с частотой обновления кинематики **10 Гц**:
* **Жизненный цикл выполнения операции:**
  1. `idle` — ожидание в базовой точке $(0, 0, 0)$.
  2. `retract` — подъём резца на безопасную высоту (если требуется).
  3. `positioning` — перемещение по осям $(X, Y)$ к начальной точке операции.
  4. `plunge` — заглубление резца по оси $Z$ на заданную глубину `depth`.
  5. `drilling` / `milling` — выполнение сверления или линейной интерполяции фрезеровки до точки `end` за время `duration`.
  6. `return_home` — подъём инструмента в $Z = 0$ и возврат в начальную точку $(0, 0, 0)$ после опустошения очереди операций.
* **Публикация состояний:** текущие координаты $(X, Y, Z)$, активная фаза `commandName` и флаг завершения `finished` публикуются в топик ROS 2 `/cnc/telemetry` и передаются в сегментатор. При завершении полного цикла гарантированно отправляется финальный кадр с `commandName: "idle"` и `finished: true`.

### 3. Сегментация и отправка телеметрии (`app/segmenter.py`)
* Полезная нагрузка телеметрии сериализуется в JSON, кодируется в **Base64** и нарезается на сегменты фиксированного размера (`SEGMENT_MAX_BYTES`).
* Каждый сегмент оборачивается в транспортный конверт (`sentAt`, `segmentNumber`, `totalSegments`, `payload`) и последовательно (с защитой через `asyncio.Lock` для сохранения порядка) отправляется на транспортный уровень (`POST /api/v1/segments`).

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
| :--- | :--- | :--- |
| `TRANSPORT_URL` | Адрес эндпоинта приёма сегментов транспортного уровня | `http://host.docker.internal:8001/api/v1/segments` |
| `TELEMETRY_INTERVAL_SEC` | Период генерации и отправки срезов телеметрии (в секундах) | `0.4` |
| `SEGMENT_MAX_BYTES` | Максимальный размер полезной нагрузки одного сегмента (в байтах) | `256` |
| `CUTTER_SPEED_XY` | Скорость холостого перемещения резца в плоскости XY (ед./с) | `15.0` |
| `CUTTER_SPEED_Z` | Скорость вертикального перемещения резца по оси Z (ед./с) | `5.0` |
| `HTTP_TIMEOUT_SEC` | Таймаут HTTP-запросов при отправке сегментов на транспорт | `3.0` |

## Запуск и сборка

### 1. Запуск в Docker (Production)

Соберите образ и запустите контейнер из директории `agent-level/`:

```bash
docker compose build --no-cache
docker compose up -d
```

Для подключения к транспортному уровню на удалённом узле (например, в сети ZeroTier) передайте адрес через переменную `TRANSPORT_URL`:

```bash
TRANSPORT_URL=http://<IP_ТРАНСПОРТА>:8001/api/v1/segments docker compose up -d
```

### 2. Проверка работоспособности

Проверка статуса контейнера, логов узла ROS 2 и отправки тестовой команды:

```bash
docker compose ps
docker compose logs -f agent-service
```

Отправка тестовой команды сверления через `curl`:

```bash
curl -X POST http://localhost:8002/api/v1/commands \
  -H "Content-Type: application/json" \
  -d '{
    "sender": "operator_test",
    "timestamp": "2026-11-19T18:00:00Z",
    "payload": {
      "operation": "drilling",
      "start": {"x": 10, "y": 15},
      "end": {"x": 10, "y": 15},
      "depth": 5,
      "duration": 3
    }
  }'
```
